provreq resolves the LLM provider from one authoritative source so that a provider configured once is used everywhere. Every LLM-backed step — bulk triage, forward-translation, and contract-drafting — and both the web UI and the CLI read the same System config (`.provreq/system.json`). It is written either through the UI's settings screen or by `provreq set-llm`, and lives untracked inside the subject checkout so a container rebuild cannot wipe it. When a subject has no System config, resolution falls back to the companion manifest's `llm:` block; when neither configures a provider, LLM-backed steps report honestly rather than guessing. A provider added through the UI is therefore used by the CLI, and one added by `provreq set-llm` is used by the UI.
