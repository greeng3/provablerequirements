Validating a subject's requirements project fails when a code tag names a requirement the subject does not declare. An Implements: or Verifies: tag whose requirement id matches no artifact is an orphan — a dangling reference from code to a requirement that was renamed, removed, or never existed — and the project is not validated while one stands, exactly as an unloadable artifact or a duplicate identity blocks validation. Each orphan is reported with its tag kind and source location so the operator can fix or remove it. This is the confirmation half of provreq owning traceability: the report shows orphans and validation refuses to pass with them.
