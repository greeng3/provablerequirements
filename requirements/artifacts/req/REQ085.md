The serve backend lets the operator triage the whole backlog from the web surface in one action, the way `provreq triage` does from the command line. This classifies every item that is untriaged or only seeded, using the configured LLM classifier; when no provider is configured it falls back to the honest prose-floor seed, and an item seeded that way is recorded as a seed, not as a classification, exactly as the command line records it. An item the record already answers — one carrying a stored verdict or an admitted formalization — is read off the record and never put in front of a classifier.

The run persists each batch as it lands, so a failure costs one batch rather than the whole run and the next run resumes from what landed. A run against a subject that has not been adopted is reported as the same unadopted condition the read surface uses. On success the backend returns the updated backlog, so the surface reconciles against the tool's authoritative state — including the recomputed coverage — rather than trusting its own guess.

This bulk write goes through the same source-agnostic triage machinery the command line uses, so the web surface and the command line never diverge on the backlog's classification.
