The tool converts a Doorstop requirements tree into a ReqForge project: it reads the subject's
`.doorstop.yml` documents and their items and writes a `reqforge.json` project marker plus an
`artifacts/` collection of one artifact per item, each carrying the item's prose, its original UID
preserved on `legacy.doorstopUid`, and a synthesised review-log entry standing for a non-null
Doorstop `reviewed` hash.

The artifact's on-disk name is the source UID unchanged, so the requirement id every verdict,
draft, and code reference is keyed on does not move — a subject can migrate onto ReqForge and be
read back through the same source-agnostic seam without a rename. The conversion only reads the
source tree; the whole write lands under the chosen target, which the operator reviews and commits.

This is how a subject leaves Doorstop for ReqForge storage. Doorstop remains a permanent import
boundary for subjects that keep using it — the conversion is a one-way door the operator chooses to
walk through, not a format the tool imposes.
