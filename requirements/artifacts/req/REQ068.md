A deductive checker may refuse to let its specification language reach the subject's ordinary
functions at all: a specification is a logical statement, and only the checker's own logical
functions may appear in one. A requirement's predicate, meanwhile, normally names an ordinary
function the subject calls. Where those two facts meet, no contract the operator writes on that
function can express the claim, and simply declaring the function logical is not open either —
that removes it from the program the subject compiles, so every real call site stops building.

Where a checker draws this line, the tool bridges it rather than reporting the claim uncheckable.
It proposes, for each predicate function, a logical twin stating that function's meaning in the
checker's own language, and a post-condition on the untouched program function tying the two
together. The program function keeps its body and all of its callers; it gains only a contract.
A claim is then checked against the twins, which the checker has been made to prove equal to the
real functions.

The twin is the one part that carries meaning rather than structure, so the tool never states it
on its own authority and never lets it stand unchecked. Two things follow. The tool itself writes
only the twin's name into a proof, never its content: what that name means is proposed, not
asserted, and a proposal it cannot verify is not something it may assert. And the linking
post-condition is not optional decoration — it is what makes the checker discharge the twin
against the real body, so a twin that misstates the function fails at that link, naming the
function it misstates, rather than going on to establish something false.

A twin is therefore reported to the operator distinctly from an ordinary contract, and as the
thing to read first. The checker's own check bounds how wrong a kept twin can be; it does not
relieve the operator of reading one. Where the tool cannot state a function's meaning faithfully,
it proposes nothing for that function and says so, because a guessed meaning that happens to
discharge would be the one way this arrangement could mislead.

A proposal must also leave the subject buildable. The tool writes these into the operator's own
source, so a proposal naming something that will not exist does not merely fail to help — it stops
the subject compiling, which withdraws every verdict about it, not only the one being pursued, and
leaves the operator's working tree broken by the tool that was meant to serve it. The tool
therefore checks each proposal against what will actually be there, and proposes nothing it cannot
place. The names it invents for twins are its own to choose, so it is the one that can tell an
invented name from a real one.

Withdrawing one proposal withdraws whatever depended on it. Twins refer to each other, so a twin
that survives on its own terms may still name one that was declined, and keeping it would recreate
the same broken build one step further along. The tool settles this before proposing anything, and
reports every twin it withdrew and why — a proposal silently reduced reads as a complete one, and
the operator would learn the difference from a compiler.
