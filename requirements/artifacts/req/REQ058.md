A quantified claim ranges its variable over a domain, and the tool grounds that claim only by
confirming the domain is real. Confirming it against the subject's own declarations is right for
the types the subject defines, but it is not the whole of what a program can range over: a
language supplies types of its own, and a claim about a value of one of those is as ordinary as a
claim about a value of any other. A domain the tool cannot admit is a requirement that cannot be
formalized at all, so the boundary of what counts as a real domain decides the reach of the tool.

A sort may therefore name one of the language's own primitive types. Such a sort grounds without
anything in the subject declaring it, and the read-back says exactly that: it resolved to the
language rather than to the subject, so there is no source location to confirm it against, and
the operator is told that instead of being shown a location the tool invented.

Where the subject declares a type of its own under a name the language also uses, the subject's
declaration is what the binding takes. It has a location the operator can confirm against, and
the read-back names it; the language stands only where the subject says nothing.

Only types a checkable claim can actually range over are admitted. A type that cannot be held as
a value produces a check that cannot be built, which reaches the operator as an inconclusive
verdict carrying a tool error — the very failure that grounding this early exists to prevent — so
such a type is refused at the binding instead.

Whatever a sort resolves to, what is generated for a checker must name it the way that checker
will read it. A name reached through the subject's own namespace and a name belonging to the
language are written differently, and generating either form for the other yields an artifact
that cannot be built. The distinction belongs to the layer that knows the language, and every
generator asks it rather than each keeping its own account of what the language provides.
