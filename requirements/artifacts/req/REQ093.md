Category 1 is verified by an ensemble of deductive engines, and Verus (verus-lang, backed by the
Z3 SMT solver) is wired as a fourth member alongside Kani, Creusot, and Prusti. When a grounded
category-1 requirement is verified and Verus is installed, its invariant is lowered to an additive
proof harness — a module placed inside the subject crate that asserts the invariant as a
universally quantified proposition over the bound sort, written in Verus's `verus! { }` dialect as
a `proof fn` containing an `assert(forall ...)`. The subject's own source is never edited: only the
harness module is added, under a configuration flag so a harness left behind by an interrupted run
cannot break an ordinary build, and every artifact the tool created is removed afterward, leaving
the subject exactly as it was.

Verus reasons only about code authored in its supported subset, so the invariant is established
against the subject's predicates only when the subject authored them as specification functions.
A predicate that is an ordinary function is ignored by Verus as external, and the harness that
references it cannot be checked; this is reported as an honest inconclusive that names the cause —
the subject's predicates are not authored in the Verus subset — never a guess and never a proof.
This is the Verus analogue of the toolchain ceiling the other deductive engines report: the engine
is sound in place only on a subject authored for it.

Because Verus is a deductive verifier, a discharged proof obligation establishes the property for
every execution relative to the specification. Such a pass earns the strongest basis, proven, and
its read-back must not carry the bounded-model-checking caveat that a Kani pass does. A harness is
read as proved only when the verifier reports at least one obligation verified and zero errors: a
run in which the harness module was excluded reports zero verified and must never be read as a
proof.

An undischarged obligation is not a refutation. A deductive prover that cannot discharge a goal may
have met a false claim or merely one it cannot see inside; either way there is no counterexample
witness. Such a result is recorded as an honest inconclusive unknown that names the likely cause,
never as a refutation and never as a proof. A harness that fails to compile, and a Verus toolchain
that is absent, are likewise inconclusive rather than a verdict.
