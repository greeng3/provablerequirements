A verdict's provenance names the subject commit it was produced against, and the code-drift
axis compares that name against the subject's current commit. A commit is a coarser clock than
the thing the verdict is about: the verdict record is itself committed, so storing an answer
moves the only clock the answer is measured by, and a subject that keeps its record in its own
tree can never hold a fresh verdict. The same false drift fires on a commit that touches only
the requirement documents, whose movement the per-item revision axis already owns.

Code drift is therefore decided at source granularity: a fingerprint over the subject's tracked
tree with the companion tree and the requirement documents excluded — exactly the records whose
drift other axes already detect. A commit that changes none of the fingerprinted source is not
code drift, however many such commits accumulate. The commit stays on the record for
reproducibility, and remains the deciding comparison for a verdict stored before the
fingerprint existed: freshness is never widened on a basis the stored verdict does not carry.
The fingerprint reads the committed tree, so an uncommitted edit is as invisible to it as it
always was to the commit comparison — the axis narrows what counts as drift; it does not claim
to see more.
