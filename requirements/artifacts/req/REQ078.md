When a requirement's verdict is first reached or its status changes, provreq records a durable, human-visible breadcrumb on the requirement itself, alongside the formalization admission, so a reader of the requirement sees not only that it was formalized but whether the formalization holds. The breadcrumb names the verdict's status, its basis, and whether the correspondence is mechanical or asserted, with the time it was recorded. It is appended only on the first verdict and on a status change: a re-verify that reaches the same status adds nothing, because the record is an event stream, not a per-run trace. The breadcrumb is written only where the requirement source keeps a review log; a source without one is unaffected, and the verdict stays recorded in provreq's own store regardless.
