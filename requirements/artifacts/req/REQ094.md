When provreq serves its embedded single-page app and a browser loads the app root, the application shell mounts and renders: the ProvableRequirements brand appears in the header. The raw index.html served to the browser carries only an empty root element, so the brand is present only after the client bundle executes. This is observable solely in a real browser driven against a live provreq serve deployment -- a server-side HTTP check sees the unmounted shell -- which is why it is a category-3 (WebDriver) requirement. It exercises provreq's own web UI against provreq itself, the one engine lane not otherwise dogfooded.
